## Wire decisions that supersede older assumptions

- Scoring is explicitly deferred by the product owner in the implemented backend. expectedRawXp/rawXpPerOccurrence/pendingRawXp null does not mean zero. Local proposal arithmetic is labeled provisional. Approval creates an unpublished execution activity; completion verification does not credit XP, CLUB_CREDIT or money.
- Application/staffing/publication versions are positive integers; legacy activity, club, self profile, calendar, schedule and resource versions are opaque GUIDs. publicationVersion is separate from staffing version. Staffing mutations return the changed resource GUID in id plus the next staffing version; activityId is not required in their receipts. Recruitment open uses current canManageRecruitment and isPublished. Verifier visibility follows server canVerify and per-completion canVerify, not a generic manager label. Own WORK_REVIEW and manual ATTENDANCE evidence use separate completion/attendance-claim routes.
- Self withdrawal has no JSON body. Resource DELETE has JSON expectedVersion/reason. Schedule DELETE has version query parameters and returns 204. Resource history uses total/page/pageSize; roster/application lists use totalItems/totalPages.
- Roster input is exact CSV UTF-8 `email,studentCode,campusCode,status` (optional userId). The former xlsx/fullName draft is not submitted to this API. The explicit commit replaces the semester/campus roster after the preview shows omissions.
- Calendar aliases are explicit server configuration. GUID SemesterKey and canonical code are not inferred from FA2026 labels or the current date. A missing alias/configuration is an unavailable state, not an empty invented calendar.
- Basic self images require issued intents, upload without app bearer and canonical PATCH. The verified returned URL replaces the staging URL. No IndexedDB blob is presented as persisted server media.
